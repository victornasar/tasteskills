Prism Design System

Prism is our shared library of design tokens, components, and guidelines. It helps teams ship consistent, accessible products faster.

🎨 Foundations

Color, type, and spacing built on a single token set.

🧩 Components

Production-ready, themeable UI building blocks.

♿ Accessible

WCAG 2.2 AA is the baseline, not an afterthought.

🌗 Themeable

Light and dark themes through CSS custom properties.

Installation

Install the package from the internal registry and import the base stylesheet once at your application root.

npm install @your-org/prism --registry=https://registry.internal.example.com
import "@your-org/prism/styles.css";
import { Button } from "@your-org/prism";

export default function App() {
  return <Button variant="primary">Hello Prism</Button>;
}
Note: Registry URL and package scope are placeholders. Replace them with your organization's values.

Design principles

1. Clarity over cleverness

Interfaces should be obvious. Prefer familiar patterns and plain language.

2. Consistency builds trust

Reuse components and tokens. Diverge only when a real user need demands it, and contribute the result back.

3. Accessible by default

Every component ships with keyboard support, focus states, and sufficient contrast.

Spacing

Spacing follows a 4px base scale. Use tokens to keep rhythm consistent.

Design tokens

Tokens are exposed as CSS custom properties. Override them at any scope to theme a subtree.

TokenLightDarkUsage
--color-primary#4F46E5#818CF8Primary actions, links, focus
--color-bg#FFFFFF#0E1116Page background
--color-surface#FFFFFF#171C25Cards, inputs
--color-border#E3E6EB#2A313DDividers, outlines
--radius-md8pxButtons, inputs, alerts
 
.my-feature {
  --color-primary: #0ea5e9;
  background: var(--color-surface);
  border: 1px solid var(--color-border);
  border-radius: var(--radius-md);
}

Button

Buttons trigger actions. Use one primary button per view to signal the main action.

Variants

<Button variant="primary">Primary</Button>
<Button variant="secondary">Secondary</Button>
<Button variant="ghost">Ghost</Button>
<Button variant="danger">Delete</Button>
<Button disabled>Disabled</Button>

Sizes

Props

PropTypeDefaultDescription
variant"primary" | "secondary" | "ghost" | "danger""primary"Visual style of the button.
size"sm" | "md" | "lg""md"Controls padding and font size.
disabledbooleanfalsePrevents interaction and dims the button.
onClick(e) => void—Click handler.
Do
Use verbs that describe the outcome: “Save changes”, “Invite member”.
Don't
Use vague labels like “OK” or “Submit” or place multiple primary buttons together.

Text input

Inputs collect short-form text. Always pair with a visible label.

We'll never share your email.
Name must be at least 3 characters. 
<TextInput
  label="Project name"
  value={name}
  error="Name must be at least 3 characters."
  onChange={setName}
/>

Badge

Badges label status or categories. Keep text short — one or two words.

Draft Active Pending Failed 
<Badge tone="success">Active</Badge>

Alert

Alerts surface important, contextual messages inline. Use role="alert" only for urgent messages.

ℹ️ A new version of Prism is available.
✅ Your changes were saved.
⚠️ Your session expires in 5 minutes.
<Alert tone="warning">Your session expires in 5 minutes.</Alert>

Switch

Switches toggle a single setting on or off, taking effect immediately.

<Switch checked={enabled} onChange={setEnabled} label="Email notifications" />

Accessibility

Accessibility is a shared responsibility between the design system and product teams.

AreaRequirement
ContrastText ≥ 4.5:1; large text and UI boundaries ≥ 3:1.
KeyboardAll interactive elements reachable and operable via keyboard with visible focus.
LabelsEvery form control has a programmatically associated label.
MotionRespect prefers-reduced-motion for non-essential animation.

Contributing

Prism improves through contributions. Before building something new, check whether an existing component can be extended.

  1. Open a proposal describing the problem, user need, and prior art.
  2. Design review with the Prism maintainers.
  3. Implement with tests, docs, and accessibility checks.
  4. Submit a pull request and request review.
