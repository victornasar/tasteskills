Flux.js

A tiny, dependency-free library for reactive state and declarative DOM updates. Under 2 KB gzipped.

⚡ Fine-grainedOnly the effects that read a value re-run when it changes.
🪶 TinyNo dependencies, no build step required.

🔒 TypedFirst-class TypeScript definitions included.

Installation

Install with your package manager of choice:

npm install fluxjs
# or
pnpm add fluxjs
yarn add fluxjs

Or load it directly in the browser as an ES module:

<script type="module">
  import { store, effect } from "https://cdn.example.com/fluxjs@2/index.js";
</script>

Quick Start

Create a store, derive a value, and bind it to the DOM:

import { store, computed, bind } from "fluxjs";

const state = store({ count: 0 });
const double = computed(() => state.count * 2);

bind("#out", () => `${state.count} × 2 = ${double.value}`);

document.querySelector("#inc").onclick = () => state.count++;

Reactive State

A store wraps a plain object in a Proxy. Reading a property inside an effect subscribes to it; writing a property notifies subscribers.

const user = store({ name: "Ada", tags: [] });
user.name = "Grace";       // triggers dependents
user.tags.push("admin");  // nested objects are reactive too
Stores are deeply reactive by default. Pass { deep: false } to track only top-level keys.

Computed Values

Computed values are lazily evaluated and cached until one of their dependencies changes.

const cart = store({ items: [{ price: 5 }, { price: 7 }] });
const total = computed(() => cart.items.reduce((s, i) => s + i.price, 0));
console.log(total.value); // 12

Effects

Effects run immediately, then re-run whenever a value they read changes. Return a function to clean up before the next run.

const stop = effect(() => {
  const id = setInterval(tick, state.interval);
  return () => clearInterval(id);
});
stop(); // dispose

DOM Binding

bind connects a selector or element to a function. The element's text is updated whenever the function's dependencies change. Use options to bind attributes or HTML.

bind("#title", () => state.title);
bind("#link", () => state.url, { attr: "href" });
Binding writes text via textContent by default, so values are never parsed as HTML. Only use { html: true } with trusted or sanitized content.

API Reference

store(initial, options?)

Creates a reactive proxy around initial.

OptionTypeDefaultDescription
deepbooleantrueMake nested objects reactive.
namestring—Label shown in debug output.

Returns: a reactive proxy of the same shape as initial.

computed(fn)

Returns an object with a read-only .value that is recomputed lazily when dependencies change.

effect(fn, options?)

Runs fn and tracks its dependencies. Returns a stop() function.

OptionTypeDefaultDescription
flush"sync" | "microtask""microtask"When re-runs are scheduled.

bind(target, fn, options?)

target is a CSS selector or Element. Returns a stop() function.

OptionTypeDescription
attrstringSet this attribute instead of text.
htmlbooleanUse innerHTML (trusted content only).

batch(fn)

Groups multiple writes so dependents run once afterwards.

batch(() => {
  state.a = 1;
  state.b = 2;
}); // effects run once

TypeScript

Types are inferred from the initial object:

interface Todo { id: number; done: boolean }
const todos = store<{ list: Todo[] }>({ list: [] });

FAQ

Does Flux.js work with React or Vue?

Yes. Flux is framework-agnostic; subscribe with effect inside your framework's lifecycle hooks and call stop() on teardown.

Which browsers are supported?

Any browser with Proxy support — all evergreen browsers and Node 16+.

Why isn't my effect re-running?

Make sure you read the value inside the effect and access it through the store proxy, not a destructured copy.
