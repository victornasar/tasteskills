StrataDB Documentation

StrataDB is a distributed, ACID-compliant database that combines a relational engine with native document and time-series storage in a single layered architecture.

⚡ Fast by design

Log-structured storage with adaptive compaction delivers low-latency reads and high write throughput.

🔒 Serializable

Snapshot isolation by default, with serializable transactions across shards.

🌐 Scales out

Automatic sharding and Raft-based replication across regions.

🧩 Multi-model

Tables, JSON documents and time-series data queried with one language.

New here? Start with the Quickstart. Operating a cluster in production? Jump to Replication & Clustering.

Quickstart

Get a local single-node instance running in under five minutes.

1. Start a server

docker run -d --name strata -p 5480:5480 \
  -v strata-data:/var/lib/stratadb \
  stratadb/stratadb:4.2

2. Connect with the shell

docker exec -it strata strata shell
# strata> connected to 127.0.0.1:5480 (v4.2.0)

3. Create and query data

CREATE TABLE users (
  id     UUID PRIMARY KEY DEFAULT gen_id(),
  email  TEXT UNIQUE NOT NULL,
  profile JSON,
  created TIMESTAMP DEFAULT now()
);

INSERT INTO users (email, profile)
VALUES ('ada@example.com', '{"plan":"pro","tags":["admin"]}');

SELECT email, profile->>'plan' AS plan
FROM users WHERE profile @> '{"tags":["admin"]}';
TipUse \timing on in the shell to print execution time for every statement.

Data Model

StrataDB organizes data in three strata, all addressable from the same query language and joinable with each other:

StratumBest forDeclared with
RelationalStructured entities, joins, constraintsCREATE TABLE
DocumentFlexible, nested JSONCREATE COLLECTION
Time-seriesMetrics, events, IoTCREATE SERIES

Supported types

INT, BIGINT, DECIMAL(p,s), FLOAT, BOOL, TEXT, BYTES, UUID, TIMESTAMP, INTERVAL, JSON, VECTOR(n), and arrays of any of these (e.g. TEXT[]).

Time-series example

CREATE SERIES cpu_metrics (
  host   TEXT TAG,
  region TEXT TAG,
  usage  FLOAT
) RETENTION '90 days' DOWNSAMPLE '1h' AFTER '7 days';

Querying with StrataQL

StrataQL is a superset of standard SQL with first-class operators for JSON paths, time windows and vector similarity.

JSON operators

OperatorDescription
->Get JSON element as JSON
->>Get JSON element as text
@>Containment test
?Key exists

Time windows

SELECT time_bucket('5m', ts) AS bucket,
       host, avg(usage) AS avg_cpu
FROM cpu_metrics
WHERE ts > now() - INTERVAL '1 hour'
GROUP BY bucket, host
ORDER BY bucket DESC;

Vector similarity

SELECT id, title
FROM articles
ORDER BY embedding <-> '[0.12, 0.98, 0.33]'::VECTOR(3)
LIMIT 10;
NoteVector queries without an index fall back to an exact scan. Create an HNSW index for datasets over 100k rows.

Transactions

All statements run inside a transaction. By default StrataDB uses snapshot isolation; request SERIALIZABLE when you need protection against write skew.

BEGIN ISOLATION LEVEL SERIALIZABLE;
  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;

Serialization conflicts return error code 40001. Clients should retry the whole transaction with exponential backoff.

Replication & Clustering

Data is split into ranges (default 512 MB). Each range is replicated using Raft, so a write is acknowledged once a majority of replicas have persisted it.

Bootstrapping a cluster

# On node 1
strata start --node-id=1 --listen=10.0.0.1:5480 --join=10.0.0.1:5480,10.0.0.2:5480,10.0.0.3:5480
# On nodes 2 and 3, change --node-id and --listen, then run once:
strata cluster init --host=10.0.0.1:5480

Replication factor

The default factor is 3, tolerating one node failure. Use 5 to tolerate two simultaneous failures.

ALTER DATABASE app CONFIGURE ZONE USING
  num_replicas = 5,
  constraints = '[+region=us-east, +region=eu-west]';
WarningRunning an even number of voting replicas does not improve fault tolerance and increases write latency.

Backup & Restore

StrataDB supports online full and incremental backups to object storage, plus point-in-time recovery (PITR) using the write-ahead log.

# Full backup
strata backup create --to s3://my-bucket/strata/full-2026-11-17

# Incremental
strata backup create --incremental-from s3://my-bucket/strata/full-2026-11-17 \
  --to s3://my-bucket/strata/inc-001

# Restore to a point in time
strata backup restore --from s3://my-bucket/strata/full-2026-11-17 \
  --as-of "2026-11-17T09:30:00Z"
RecommendationSchedule a full backup weekly and incrementals hourly, and test restores regularly in a staging cluster.

Security

Encryption

TLS 1.3 is required for client and node-to-node traffic. Data at rest is encrypted with AES-256; keys can be managed by an external KMS.

Role-based access control

CREATE ROLE analyst;
GRANT SELECT ON ALL TABLES IN SCHEMA reporting TO analyst;
CREATE USER maria WITH PASSWORD '<use-a-secret-manager>' ROLE analyst;

Row-level security policies and audit logging are available via CREATE POLICY and the audit.enabled setting.

Production checklistDisable the default admin account, rotate certificates before expiry, and restrict port 5480 to trusted networks.

Configuration

Settings can be supplied by flag, environment variable (STRATA_*) or the config file at /etc/stratadb/strata.toml. Precedence is flag > env > file.

# /etc/stratadb/strata.toml
[server]
listen = "0.0.0.0:5480"
max_connections = 500

[storage]
data_dir = "/var/lib/stratadb"
cache_size = "8GiB"
compaction = "adaptive"

[tls]
cert = "/etc/stratadb/tls/node.crt"
key  = "/etc/stratadb/tls/node.key"

[audit]
enabled = true

Troubleshooting

Error 40001: serialization failure

Two concurrent transactions conflicted. Retry the transaction from the start; if this is frequent, reduce transaction scope or contention on hot rows.

Node cannot join the cluster

Verify that all nodes can reach each other on the listen port, clocks are synced within 500 ms (NTP/chrony), and certificates share the same CA.

Slow queries

Run EXPLAIN ANALYZE and look for full scans. Check strata cluster status for under-replicated ranges and compaction backlog.

Still stuck?Run strata doctor --bundle and attach the output when contacting support.
