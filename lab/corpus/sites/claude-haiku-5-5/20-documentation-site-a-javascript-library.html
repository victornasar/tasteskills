Tinystate

A tiny, dependency-free reactive state library for JavaScript. About 1.5 KB gzipped, with a simple API and first-class TypeScript support.

Tinystate gives you observable stores that notify subscribers when their values change. It works in the browser, in Node.js, and in any framework or none at all.

  • Small: 1.5 KB gzipped, zero dependencies.
  • Predictable: updates are synchronous and explicit.
  • Typed: full TypeScript inference for state and selectors.
  • Portable: runs in browsers, Node.js 18+, Deno, and Bun.

Installation

Install from npm:

npm install tinystate

Or load it directly from a CDN as an ES module:

<script type="module">
  import { createStore } from "https://cdn.example.com/tinystate@2.4.0/dist/tinystate.esm.js";
</script>

Quick start

Create a store, read its value, update it, and subscribe to changes:

import { createStore } from "tinystate";

const counter = createStore({ count: 0 });

const unsubscribe = counter.subscribe((state) => {
  console.log("count is now", state.count);
});

counter.set((state) => ({ count: state.count + 1 })); // logs: count is now 1
counter.get();                                         // { count: 1 }

unsubscribe();

Stores

A store holds a single state object. Read it with get() and replace it with set(). Updates always produce a new object, so comparisons are cheap and reliable.

Tip Never mutate the object returned by get(). Always return a new object from set().

Derived values

Use select() to compute a value from a store. Derived selectors only notify subscribers when their result changes, using Object.is by default.

const cart = createStore({ items: [{ price: 4, qty: 2 }, { price: 10, qty: 1 }] });

const total = select(cart, (s) =>
  s.items.reduce((sum, item) => sum + item.price * item.qty, 0)
);

total.get(); // 18

Subscriptions

Subscribers receive the new state after every change. Always keep the unsubscribe function returned by subscribe() and call it when you no longer need updates, for example when a component unmounts.

Batching

By default, each set() call notifies subscribers immediately. Wrap several updates in batch() to notify once at the end.

import { batch } from "tinystate";

batch(() => {
  store.set({ loading: true });
  store.set({ loading: false, data: result });
}); // subscribers are notified once

createStore()

createStore<T>(initialState: T, options?: StoreOptions<T>): Store<T>

Creates a new store with the given initial state.

OptionTypeDefaultDescription
namestringundefinedLabel used in devtools and error messages.
equals(a, b) => booleanObject.isCustom equality check to skip redundant notifications.
onError(err) => voidconsole.errorCalled when a subscriber throws.

select()

select<T, R>(store: Store<T>, selector: (state: T) => R): Store<R>

Returns a read-only derived store that recomputes when the source store changes. Results are memoized.

subscribe()

store.subscribe(listener: (state: T) => void): () => void

Registers a listener and returns a function that removes it. The listener is called immediately with the current state, then after each change.

batch()

batch(fn: () => void): void

Runs fn and defers subscriber notifications until it returns. Nested calls are supported.

reset()

store.reset(): void

Restores the store to its initial state and notifies subscribers.

Using with frameworks

Tinystate works with any UI framework. Choose the tab that matches your stack.

import { useSyncExternalStore } from "react";

function useStore(store) {
  return useSyncExternalStore(store.subscribe, store.get);
}

function Counter() {
  const state = useStore(counter);
  return <button onClick={() => counter.set(s => ({ count: s.count + 1 }))}>{state.count}</button>;
}
import { shallowRef, onUnmounted } from "vue";

export function useStore(store) {
  const state = shallowRef(store.get());
  const unsubscribe = store.subscribe((s) => (state.value = s));
  onUnmounted(unsubscribe);
  return state;
}
const output = document.querySelector("#count");

counter.subscribe((state) => {
  output.textContent = state.count;
});

Persisting state

Pair a store with localStorage or any other storage layer by subscribing to changes and writing them out:

const prefs = createStore(JSON.parse(localStorage.getItem("prefs")) ?? { theme: "light" });

prefs.subscribe((state) => {
  localStorage.setItem("prefs", JSON.stringify(state));
});

Testing

Stores are plain objects with no global side effects, so you can create a fresh instance per test:

import { test, expect } from "vitest";
import { createStore } from "tinystate";

test("increments the count", () => {
  const store = createStore({ count: 0 });
  store.set((s) => ({ count: s.count + 1 }));
  expect(store.get().count).toBe(1);
});

FAQ

Does Tinystate support async actions?

Yes. Call set() whenever your async work finishes. Tinystate does not impose a specific async pattern.

Can I use it without a build step?

Yes. Load the ES module build from a CDN, as shown in Installation.

Is it compatible with TypeScript?

Yes. Types are inferred from the initial state, and selectors are fully typed.
