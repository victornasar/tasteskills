Getting Started / Introduction

NovaDB Documentation

NovaDB is a distributed, ACID-compliant document database built for low-latency workloads. Store, query, and scale your data with a single binary and a familiar query language.

Get started → API reference

What is NovaDB?

NovaDB stores data as versioned JSON-like documents grouped into collections. It provides a write-ahead log for durability, a cost-based query planner, and built-in replication. Unlike many document stores, NovaDB enforces schema constraints optionally, so you can start flexible and tighten guarantees as your application matures.

Key features

FeatureDescription
ACID transactionsMulti-document transactions with serializable isolation by default.
Secondary indexesB-tree, hash, and full-text indexes on any field path.
ReplicationSynchronous and asynchronous replicas with automatic failover.
EncryptionTLS 1.3 in transit and AES-256 encryption at rest.
ObservabilityPrometheus metrics endpoint and structured JSON logs.

Getting Started / Quickstart

Quickstart

This guide gets a local NovaDB instance running and walks you through creating a collection, inserting documents, and running a query.

On this page
  1. Install the server
  2. Start a local instance
  3. Connect with the CLI
  4. Insert and query data

1. Install the server

NovaDB ships as a single static binary for macOS, Linux, and Windows. Install it with the package manager of your choice:

# macOS
brew tap novadb/tap
brew install novadb
# Debian / Ubuntu
curl -fsSL https://pkg.novadb.dev/gpg | sudo gpg --dearmor -o /usr/share/keyrings/novadb.gpg
echo "deb [signed-by=/usr/share/keyrings/novadb.gpg] https://pkg.novadb.dev/apt stable main" | sudo tee /etc/apt/sources.list.d/novadb.list
sudo apt update && sudo apt install novadb
docker run -d --name novadb \
  -p 7600:7600 \
  -v novadb-data:/var/lib/novadb \
  novadb/novadb:4.2

2. Start a local instance

Start the server in development mode. It listens on localhost:7600 by default and stores data in ./novadb-data.

# Start the server in dev mode
novadb serve --dev

# Expected output
2026-11-17T09:12:04Z INFO  NovaDB 4.2.0 starting
2026-11-17T09:12:04Z INFO  Listening on 127.0.0.1:7600
2026-11-17T09:12:04Z INFO  Ready to accept connections
Development mode is not for production

--dev disables authentication and TLS. Never expose a dev instance to a network you don't control. See Security for production setup.

3. Connect with the CLI

The nova CLI is bundled with the server. Open a shell session:

nova shell --host localhost:7600

4. Insert and query data

Create a collection, insert a document, and query it back using NovaQL:

-- Create a collection
CREATE COLLECTION users;

-- Insert a document
INSERT INTO users
  VALUES {"name": "Ada Lovelace", "role": "engineer", "age": 36};

-- Query it back
SELECT name, role FROM users WHERE age > 30;
You're up and running

Next, read Core Concepts to understand how collections, documents, and revisions fit together.

Installation

Production deployments have a few more requirements than the quickstart. This page covers system requirements and installation options.

System requirements

ComponentMinimumRecommended
CPU2 cores8+ cores
Memory2 GB16 GB+
Storage10 GB SSDNVMe SSD, 100 GB+
OSLinux (kernel 5.4+), macOS 13+, Windows Server 2019+Linux (kernel 6.1+)

Install from a package manager

See the tabs in the Quickstart for Homebrew, apt, and Docker. For RPM-based systems:

sudo rpm --import https://pkg.novadb.dev/gpg
sudo dnf install novadb

Verify the installation

novadb --version
# NovaDB 4.2.0 (build 8f3a1c2, go1.23)

Run as a system service

On Linux with systemd, enable the bundled unit file to start NovaDB at boot:

sudo systemctl enable --now novadb
sudo systemctl status novadb
Upgrading from 3.x

Version 4.0 changed the on-disk format. Run novadb migrate --from 3.x against a stopped node before starting 4.x. Take a backup first. See the changelog for details.

Getting Started / Core Concepts

Core Concepts

A few building blocks show up everywhere in NovaDB. Understanding them makes the rest of the docs much easier to follow.

Databases, collections, and documents

A database is a namespace that holds collections. A collection is a group of related documents, similar to a table in a relational database. A document is a JSON-like object with a unique _id field that NovaDB generates if you don't provide one.

Revisions

Every write creates a new revision of a document. Revisions are kept for the retention window set by storage.revision_retention (default: 24 hours), enabling point-in-time reads and conflict detection.

Consistency model

LevelGuaranteeLatency
strongReads reflect all committed writesHigher
boundedReads may lag by up to 5 secondsMedium
eventualReads may return stale dataLowest

Nodes and clusters

A node is a running NovaDB process. Nodes form a cluster that shares a consensus group. One node is elected leader; the others are followers. See Replication for details.

Guides / Data Modeling

Data Modeling

NovaDB is schema-optional. You can store free-form documents, or define a schema to enforce structure on writes.

Embedding vs. referencing

Embed data that is always read together and bounded in size. Reference data that is shared, large, or frequently updated independently.

// Embedded: order items live inside the order
{
  "_id": "ord_1001",
  "customer_id": "cus_42",
  "items": [
    { "sku": "BOOK-77", "qty": 2, "price": 19.99 }
  ]
}

Defining a schema

Attach a schema to a collection to validate documents on write:

CREATE COLLECTION orders
  WITH SCHEMA {
    "type": "object",
    "required": ["customer_id", "items"],
    "properties": {
      "customer_id": { "type": "string" },
      "items":       { "type": "array" }
    }
  };
Tip

Start schema-free while prototyping. Add a schema once field names and types stabilize.

Guides / Querying with NovaQL

Querying with NovaQL

NovaQL is a SQL-like language with native support for nested document paths and JSON operators.

Basic selects

SELECT _id, customer_id, items[0].sku
FROM orders
WHERE total(items) > 50
ORDER BY _id DESC
LIMIT 20;

Aggregations

SELECT customer_id, COUNT(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING order_count >= 5;

Updating documents

UPDATE orders
  SET status = "shipped"
  WHERE _id = "ord_1001";
Always include a WHERE clause on UPDATE and DELETE

Without one, the statement affects every document in the collection. Use --confirm-all to override this safeguard intentionally.

Query plans

Prefix any query with EXPLAIN to see how NovaDB will execute it:

EXPLAIN SELECT * FROM orders WHERE customer_id = "cus_42";

Guides / Indexes

Indexes

Indexes speed up reads at the cost of additional storage and slightly slower writes. Create them on fields you filter or sort by frequently.

Creating an index

CREATE INDEX idx_orders_customer
  ON orders (customer_id)
  USING btree;

Index types

TypeBest forSupports range
btreeEquality and range queries, sortingYes
hashExact-match lookupsNo
fulltextText search with stemmingNo

Compound indexes

CREATE INDEX idx_orders_status_date
  ON orders (status, created_at DESC);

Column order matters. The index above supports queries filtering on status alone, or on status and created_at, but not on created_at alone.

Check usage

Run SHOW INDEX STATS orders; periodically. Indexes with zero reads over 30 days are candidates for removal.

Guides / Transactions

Transactions

Multi-document transactions give you atomic, isolated writes across collections.

Basic transaction

BEGIN;
  UPDATE accounts SET balance = balance - 100 WHERE _id = "acc_a";
  UPDATE accounts SET balance = balance + 100 WHERE _id = "acc_b";
COMMIT;

Isolation levels

LevelDirty readNon-repeatable readPhantom read
READ COMMITTEDNoPossiblePossible
SNAPSHOTNoNoPossible
SERIALIZABLE (default)NoNoNo

Handling conflicts

Under SERIALIZABLE, a transaction that conflicts with a concurrent commit fails with error NOVA-TXN-409. Retry the transaction with exponential backoff:

async function withRetry(fn, attempts = 5) {
  for (let i = 0; i < attempts; i++) {
    try {
      return await fn();
    } catch (err) {
      if (err.code !== "NOVA-TXN-409" || i === attempts - 1) throw err;
      await sleep(2 ** i * 100);
    }
  }
}

Guides / Replication

Replication

Run a three-node cluster for high availability. NovaDB uses Raft consensus and fails over automatically when the leader is lost.

Topology

Use an odd number of voting members. Three nodes tolerate one failure; five tolerate two. Add non-voting read replicas for analytics workloads.

Configure a node

# /etc/novadb/novadb.yaml (on node-1)
cluster:
  node_id: node-1
  peers:
    - node-2.internal:7700
    - node-3.internal:7700
  replication_mode: sync   # or: async
Sync vs. async

sync waits for a majority to acknowledge each write, guaranteeing no loss on failover. async is faster but may lose the most recent writes if the leader fails.

Check cluster health

nova cluster status

# NODE     ROLE      STATE    LAG
# node-1   leader    healthy  0ms
# node-2   follower  healthy  3ms
# node-3   follower  healthy  4ms

Operations / Backup & Restore

Backup & Restore

NovaDB supports consistent online snapshots and point-in-time recovery using the write-ahead log.

Create a snapshot

nova backup create --output /backups/novadb-$(date +%F).nbk

Snapshots are taken without blocking writes. The backup is consistent as of the moment the command started.

Restore

# Stop the node first
sudo systemctl stop novadb

nova backup restore --input /backups/novadb-2026-11-16.nbk --data-dir /var/lib/novadb

sudo systemctl start novadb

Point-in-time recovery

Restore a snapshot, then replay the WAL up to a timestamp:

nova backup restore --input snapshot.nbk --replay-wal --until "2026-11-16T14:30:00Z"
Test your restores

A backup you haven't restored is not a backup. Run a restore into a scratch environment on a regular schedule.

Operations / Security

Security

NovaDB encrypts data in transit and at rest, and supports role-based access control out of the box.

Authentication

Create users and assign roles with CREATE USER and GRANT:

CREATE USER analyst WITH PASSWORD 'use-a-long-random-value';
GRANT READ ON orders TO analyst;

Enable TLS

network:
  tls:
    enabled: true
    cert_file: /etc/novadb/tls/server.crt
    key_file:  /etc/novadb/tls/server.key
    min_version: "1.3"

Encryption at rest

Enable AES-256 encryption by pointing NovaDB at a key file or KMS. Keys can be rotated without downtime using nova key rotate.

Lost keys mean lost data

Back up your encryption keys separately from data backups. Without the key, encrypted snapshots cannot be restored.

Reference / HTTP API

HTTP API

Every operation available in the CLI is also available over the REST API on port 7600.

Insert a document

POST /v4/collections/{name}/documents
curl -X POST https://localhost:7600/v4/collections/users/documents \
  -H "Authorization: Bearer $NOVA_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Ada Lovelace", "role": "engineer"}'
{
  "_id": "doc_8h2K1pQ",
  "_rev": 1,
  "created_at": "2026-11-17T09:14:22Z"
}

Get a document

GET /v4/collections/{name}/documents/{id}

Add ?rev=N to read a specific revision within the retention window.

Delete a document

DELETE /v4/collections/{name}/documents/{id}

Deletes are soft by default. Pass ?hard=true to remove all revisions immediately.

Run a query

POST /v4/query
{
  "statement": "SELECT name FROM users WHERE age > ?",
  "params": [30],
  "consistency": "bounded"
}

Errors

Errors return a JSON body with code, message, and request_id. Include the request_id when contacting support.

{
  "code": "NOVA-QRY-422",
  "message": "unexpected token 'FORM' at position 14",
  "request_id": "req_01J9Z3K4"
}

Reference / Configuration

Configuration

NovaDB reads configuration from novadb.yaml. Every key can be overridden with an environment variable prefixed with NOVA_.

Common options

KeyDefaultDescription
server.port7600Client API port
storage.data_dir./novadb-dataLocation of database files
storage.revision_retention24hHow long old revisions are kept
storage.cache_size50% of RAMBuffer pool size
slow_query_threshold500msQueries slower than this are logged
log.levelinfodebug, info, warn, error

Example

server:
  port: 7600
storage:
  data_dir: /var/lib/novadb
  revision_retention: 48h
  cache_size: 8GB
slow_query_threshold: 250ms
log:
  level: info
