Design System

A shared library of tokens, components, and guidelines that help our teams build consistent, accessible internal tools faster.

This documentation covers the visual foundations, reusable components, and contribution workflow for the design system. Use it as the single source of truth when designing or building internal interfaces.

Who this is for Product designers, frontend engineers, and anyone shipping internal tools that need to look and behave consistently.

Principles

Clarity over decoration

Every element should help users understand what they can do and what will happen next.

Consistency by default

Reuse existing tokens and components before creating new ones. Variation should be intentional and documented.

Accessible from the start

Meet WCAG 2.1 AA contrast, keyboard navigation, and screen reader requirements in every component.

Installation

Install the design system package into your project:

npm install @acme/design-system

Then import the base stylesheet at the root of your application:

import "@acme/design-system/styles.css";

Contributing

To propose a new component or change to an existing one:

  1. Open a request in the design system tracker with a use case and at least two example screens.
  2. Check the existing component library for overlap.
  3. Build the component with tokens only, no hard-coded values.
  4. Add accessibility notes and at least one usage example.
  5. Request review from the design system maintainers.
