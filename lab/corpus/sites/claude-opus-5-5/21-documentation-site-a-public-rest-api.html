Orbit API Reference

The Orbit API lets you manage projects, tasks, and real-time events programmatically. It is organized around REST, uses predictable resource-oriented URLs, accepts JSON request bodies, and returns JSON responses with standard HTTP status codes.

BASEhttps://api.orbit.example/v2

All requests must be made over HTTPS. Requests made over plain HTTP will be rejected. Timestamps are returned in ISO 8601 format in UTC, and IDs are opaque strings prefixed by resource type (for example prj_ or tsk_).

🔑 AuthenticationGet an API key and authorize requests. 📁 ProjectsCreate and organize workspaces. ✅ TasksTrack work items inside projects. 📡 WebhooksReceive events as they happen.

Authentication

The Orbit API uses bearer tokens. Create and revoke keys from Dashboard → Settings → API keys. Include your key in the Authorization header of every request.

Keys come in two flavors:

PrefixUse
sk_live_Production data. Keep it secret and server-side only.
sk_test_Sandbox data. Safe for development; never touches live resources.
Keep keys secret. Never embed secret keys in client-side code, mobile apps, or public repositories. Rotate a key immediately if you suspect it has been exposed.

Requests without a valid key return 401 Unauthorized. Keys lacking a required scope return 403 Forbidden.

Authenticated request
curl https://api.orbit.example/v2/projects \
  -H "Authorization: Bearer sk_test_EXAMPLE_KEY_REDACTED"

Errors

Orbit uses conventional HTTP response codes. Codes in the 2xx range indicate success, 4xx indicate a problem with the request, and 5xx indicate a problem on our side.

StatusMeaning
200 OKRequest succeeded.
201 CreatedResource created.
204 No ContentSucceeded with no response body.
400 Bad RequestMalformed JSON or missing required parameter.
401 UnauthorizedNo valid API key provided.
403 ForbiddenKey lacks permission for this resource.
404 Not FoundResource doesn't exist.
409 ConflictRequest conflicts with current state (e.g. idempotency key reuse).
422 UnprocessableValidation failed.
429 Too Many RequestsRate limit exceeded.
5xxServer error. Safe to retry with backoff.
Error response
{
  "error": {
    "type": "validation_error",
    "code": "parameter_missing",
    "message": "The 'name' parameter is required.",
    "param": "name",
    "request_id": "req_8fK2mQ1xZt"
  }
}

Pagination

All list endpoints use cursor-based pagination. Responses include a has_more flag and a next_cursor you pass back to fetch the following page.

Query parameters

limitintegeroptional

Number of objects to return, between 1 and 100. Defaults to 20.

cursorstringoptional

The next_cursor value from a previous response.

Paginated response
{
  "object": "list",
  "data": [ /* … */ ],
  "has_more": true,
  "next_cursor": "eyJpZCI6InByal8yMCJ9"
}

Rate limits

Each API key may make up to 100 requests per second in live mode and 25 per second in test mode. Every response includes headers describing your current usage.

HeaderDescription
X-RateLimit-LimitRequests allowed in the current window.
X-RateLimit-RemainingRequests left in the current window.
X-RateLimit-ResetUnix timestamp when the window resets.
Retry-AfterSeconds to wait (only on 429).
Use exponential backoff with jitter when retrying 429 and 5xx responses. For safe retries of POST requests, send an Idempotency-Key header.
429 response headers
HTTP/1.1 429 Too Many Requests
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1795392000
Retry-After: 2

Create a project

POST/v2/projects

Creates a new project. The authenticated key's owner becomes the project owner.

Body parameters

namestringrequired

Display name, 1–120 characters.

descriptionstringoptional

Markdown description, up to 10,000 characters.

colorstringoptional

Hex color used in the UI, e.g. #4f46e5.

metadataobjectoptional

Up to 50 key/value string pairs for your own use.

Headers

Idempotency-Keystringoptional

Unique value (e.g. a UUID) that makes the request safe to retry for 24 hours.

curl https://api.orbit.example/v2/projects \
  -H "Authorization: Bearer $ORBIT_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c2a8e-3b7d-4c11-9e2f-0a5b8d7c4e21" \
  -d '{"name":"Mobile app","color":"#10b981"}'
const res = await fetch("https://api.orbit.example/v2/projects", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.ORBIT_API_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": crypto.randomUUID(),
  },
  body: JSON.stringify({ name: "Mobile app", color: "#10b981" }),
});
const project = await res.json();
import os, uuid, requests

r = requests.post(
    "https://api.orbit.example/v2/projects",
    json={"name": "Mobile app", "color": "#10b981"},
    headers={
        "Authorization": f"Bearer {os.environ['ORBIT_API_KEY']}",
        "Idempotency-Key": str(uuid.uuid4()),
    },
)
project = r.json()

Webhooks

Webhooks push events to your server via HTTPS POST as they happen. Register endpoints under Dashboard → Developers → Webhooks. Respond with any 2xx status within 10 seconds; failed deliveries are retried with exponential backoff for up to 3 days.

Event types

EventFired when
project.createdA project is created.
project.archivedA project's status becomes archived.
project.deletedA project is permanently deleted.
task.createdA task is added.
task.updatedAny task field changes.
task.completedA task moves to done.
Events may arrive out of order or more than once. Use the event id to deduplicate.
Event payload
{
  "id": "evt_Q2c7nP0sLm",
  "type": "task.completed",
  "created_at": "2026-11-17T10:03:51Z",
  "data": {
    "object": {
      "id": "tsk_Vb51pXa0",
      "object": "task",
      "state": "done"
    },
    "previous": { "state": "in_progress" }
  }
}

Verifying signatures

Every delivery includes an Orbit-Signature header of the form t=<timestamp>,v1=<hex>. The signature is an HMAC-SHA256 of "{t}.{raw_body}" keyed with your endpoint's signing secret.

  1. Parse t and v1 from the header.
  2. Reject the request if t is more than 5 minutes old.
  3. Compute the expected HMAC over the raw request body.
  4. Compare using a constant-time function.
import crypto from "node:crypto";

export function verify(rawBody, header, secret) {
  const parts = Object.fromEntries(header.split(",").map(p => p.split("=")));
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > 300) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${parts.t}.${rawBody}`)
    .digest("hex");
  const a = Buffer.from(expected), b = Buffer.from(parts.v1 ?? "");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
import hmac, hashlib, time

def verify(raw_body: bytes, header: str, secret: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    if abs(time.time() - int(parts["t"])) > 300:
        return False
    expected = hmac.new(
        secret.encode(),
        f"{parts['t']}.".encode() + raw_body,
        hashlib.sha256,
    ).hexdigest()
    return hmac.compare_digest(expected, parts.get("v1", ""))
