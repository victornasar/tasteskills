Installation #

Install Kestrel from npm using your package manager of choice:

npm install kestrel-signals
yarn add kestrel-signals
pnpm add kestrel-signals
<script type="module">
  import { signal, effect } from "https://esm.sh/kestrel-signals@2";
</script>
Requirements

Kestrel ships ES modules and CommonJS builds. It targets ES2019 and runs in all evergreen browsers and Node.js 16+.

Quick Start #

Here's everything you need in under fifteen lines. A signal holds a value, a computed derives from it, and an effect reacts to changes:

import { signal, computed, effect } from "kestrel-signals";

const count = signal(0);
const doubled = computed(() => count() * 2);

effect(() => {
  console.log(`count is ${count()}, doubled is ${doubled()}`);
});
// → count is 0, doubled is 0

count.set(5);
// → count is 5, doubled is 10

count.update((n) => n + 1);
// → count is 6, doubled is 12

Notice that you never told the effect what to watch. Kestrel tracks dependencies automatically: any signal read during an effect becomes a dependency of that effect.

Signals #

A signal is a container for a value that notifies subscribers when it changes. Read it by calling it like a function; write it with .set() or .update().

const name = signal("Ada");

name();                      // "Ada"
name.set("Grace");           // replace the value
name.update((n) => n + "!"); // derive from the previous value
name.peek();                 // read without tracking

Signals compare values with Object.is. Setting a signal to the value it already holds is a no-op and won't trigger any effects.

Mutating objects

Mutating an object inside a signal does not notify subscribers, because the reference is unchanged. Create a new object instead — user.update(u => ({ ...u, age: 37 })) — or use store() for deep reactivity.

Computed Values #

A computed is a read-only signal whose value is derived from other signals. It is lazy — the function only runs when something reads it — and memoized until one of its dependencies changes.

const first = signal("Ada");
const last = signal("Lovelace");

const fullName = computed(() => `${first()} ${last()}`);

fullName(); // "Ada Lovelace"
last.set("Byron");
fullName(); // "Ada Byron"

Computeds can depend on other computeds. Kestrel guarantees a glitch-free update order, so a computed never observes a partially updated graph.

Effects #

An effect runs a function immediately, tracks every signal it reads, and re-runs whenever one of them changes. Use effects to sync state with the outside world: the DOM, network, storage, or logs.

const theme = signal("light");

const dispose = effect(() => {
  document.body.dataset.theme = theme();

  // Optional: return a cleanup function
  return () => console.log("theme effect cleaned up");
});

// Later, stop reacting:
dispose();

If an effect returns a function, Kestrel calls it before the next run and when the effect is disposed — ideal for removing event listeners or cancelling timers.

Batching #

By default each write notifies effects synchronously. When you need to update several signals at once, wrap the writes in batch() so effects run only once, after all writes complete.

const x = signal(0);
const y = signal(0);

effect(() => console.log(x(), y()));
// → 0 0

batch(() => {
  x.set(10);
  y.set(20);
});
// → 10 20   (one run, not two)

Batches can be nested; effects flush when the outermost batch exits. See the batching button in the playground to watch this in action.

API Reference #

signal()

signal<T>(initialValue: T, options?: SignalOptions<T>): Signal<T>

Creates a writable reactive value.

ParameterTypeDescription
initialValueTThe starting value.
options.equals(a: T, b: T) => booleanCustom equality check. Defaults to Object.is.
options.namestringDebug label shown in devtools.
MemberDescription
s()Returns the current value and subscribes the active observer.
s.set(value)Replaces the value and notifies dependents if it changed.
s.update(fn)Sets the value to fn(current).
s.peek()Returns the current value without subscribing.

computed() #

computed<T>(fn: () => T, options?: { equals?, name? }): ReadonlySignal<T>

Creates a lazily evaluated, memoized, read-only signal. The returned value supports calling and .peek() but has no .set().

const items = signal([3, 1, 2]);
const sorted = computed(() => [...items()].sort((a, b) => a - b));

effect() #

effect(fn: () => void | (() => void)): () => void

Runs fn immediately and again whenever its tracked dependencies change. Returns a dispose function that unsubscribes the effect and runs any pending cleanup.

Tip

Dependencies are re-collected on every run, so conditional reads work naturally. If a branch stops reading a signal, the effect stops depending on it.

batch() #

batch<T>(fn: () => T): T

Defers effect execution until fn returns, then flushes each affected effect once. Returns whatever fn returns. Reading a computed inside a batch always yields an up-to-date value.

untrack() #

untrack<T>(fn: () => T): T

Runs fn without tracking any signals it reads. Useful when an effect needs a value but shouldn't re-run when it changes.

effect(() => {
  const id = userId();                     // tracked
  const opts = untrack(() => settings());  // not tracked
  fetchUser(id, opts);
});

store() #

store<T extends object>(initial: T): T

Wraps a plain object or array in a deep reactive proxy. Each property behaves like its own signal, so effects only re-run when the specific properties they read change.

import { store, effect } from "kestrel-signals";

const todos = store({
  filter: "all",
  items: [{ text: "Write docs", done: false }],
});

effect(() => console.log(todos.items.length));

todos.items.push({ text: "Ship v2.4", done: false }); // logs 2
todos.filter = "done";                               // does not log

    TypeScript #

    Kestrel is written in TypeScript. Types are inferred from initial values, and you can supply a generic when the initial value is narrower than the intended type.

    import { signal, computed, type Signal, type ReadonlySignal } from "kestrel-signals";

interface User { id: number; name: string }

const user = signal<User | null>(null);
const greeting: ReadonlySignal<string> = computed(() =>
  user() ? `Hello, ${user()!.name}` : "Hello, guest"
);

function bindInput(el: HTMLInputElement, s: Signal<string>) {
  el.addEventListener("input", () => s.set(el.value));
}

    FAQ #

    How do I use Kestrel with React?
    Install the companion package kestrel-react and use the useSignal(s) hook, which subscribes a component to a signal via useSyncExternalStore. Components re-render only when the signals they read change.
    Does it support server-side rendering?
    Yes. Signals are plain JavaScript and have no DOM dependency. Create state per request to avoid sharing it across users, and dispose effects when the request ends.
    What happens if an effect writes to a signal it reads?
    Kestrel detects the cycle and throws a descriptive error after 100 iterations in development builds. Prefer a computed for derived values, or use untrack() for intentional read-then-write patterns.
    Are effects synchronous?
    Yes, by default effects run synchronously after each write (or after the outermost batch). Pass a custom scheduler via configure({ scheduler: queueMicrotask }) if you prefer asynchronous flushing.
    Is there a devtools extension?
    Name your signals with { name: "..." } and enable configure({ devtools: true }) to inspect the dependency graph in the Kestrel DevTools panel.
