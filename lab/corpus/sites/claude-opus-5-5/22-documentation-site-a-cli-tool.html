Build anything, fire it once.

kiln is a fast, declarative task runner for the command line. Describe your tasks in a single Kilnfile, and kiln figures out what to run, in what order, and what it can skip.

Install kiln → Quick start
⚡ Parallel by defaultIndependent tasks run concurrently across all available cores.
🧊 Content-hashed cacheUnchanged inputs mean instant, skipped tasks — locally or shared.
📄 One readable filePlain TOML. No plugins, no DSL, no surprise magic.
👀 Watch modeRe-run only the affected tasks when files change.

Installation #

kiln ships as a single static binary with no runtime dependencies. Pick your platform:

bash
$ brew install kiln
bash
$ curl -fsSL https://kiln.example.dev/install.sh | sh

Tip: Inspect the script before piping it to a shell. It installs to ~/.local/bin unless KILN_INSTALL_DIR is set.

powershell
PS> winget install kiln.kiln
# or
PS> scoop install kiln
bash
$ cargo install kiln-cli --locked

Verify the installation:

bash
$ kiln --version
kiln 2.4.0 (aarch64-apple-darwin)

Quick start #

  1. Create a Kilnfile in your project root:
    bash
    $ kiln init
  2. Open Kilnfile and define a task:
    Kilnfile
    [tasks.build]
run     = "npm run build"
inputs  = ["src/**", "package.json"]
outputs = ["dist/**"]
  3. Run it:
    bash
    $ kiln run build
✓ build (2.31s)

$ kiln run build
✓ build (cached, 4ms)

The second run is skipped because nothing in inputs changed. That's the core idea.

The Kilnfile #

A Kilnfile is a TOML document. kiln searches the current directory and then each parent until it finds one, so you can run tasks from any subdirectory.

Kilnfile
# Project-wide settings
[kiln]
min_version = "2.0"
default     = "build"

[tasks.lint]
run    = "eslint src"
inputs = ["src/**/*.ts", ".eslintrc"]

[tasks.test]
run     = "vitest run"
deps    = ["build"]
inputs  = ["src/**", "test/**"]

[tasks.build]
run     = ["tsc -p .", "node scripts/bundle.js"]
inputs  = ["src/**", "tsconfig.json"]
outputs = ["dist/**"]

Task fields #

FieldTypeDescription
runstring | string[]Command(s) to execute. Arrays run sequentially and stop on the first failure.
depsstring[]Tasks that must succeed before this one starts.
inputsglob[]Files hashed to determine whether the task is up to date.
outputsglob[]Files produced by the task; restored from cache on a hit.
envtableEnvironment variables set for this task only.
cwdstringWorking directory, relative to the Kilnfile.
cacheboolSet to false to always run. Default true when inputs is set.
descriptionstringShown in kiln list.

Task dependencies #

kiln builds a directed acyclic graph from every task's deps. Tasks with no path between them run in parallel; everything else waits for its dependencies.

bash
$ kiln run test --graph
test
└── build
    ├── codegen
    └── assets

Warning: Cycles are a hard error. kiln will print the cycle path (e.g. a → b → c → a) and exit with code 3.

Caching #

Before running a task, kiln computes a fingerprint from:

  • The contents of every file matching inputs
  • The task's run command and env
  • The fingerprints of all its deps

If the fingerprint matches a previous successful run, kiln restores the recorded outputs and skips execution. The cache lives in .kiln/cache by default.

Remote cache #

Share cache hits across machines and CI by pointing kiln at any S3-compatible bucket or HTTP endpoint:

Kilnfile
[cache]
remote = "s3://my-team-kiln-cache"
mode   = "read-write"   # or "read-only" for local dev

Variables & environment #

Define reusable values under [vars] and reference them with ${name}. Environment variables are available as ${env.NAME}.

Kilnfile
[vars]
out = "dist"

[tasks.deploy]
run  = "rsync -a ${out}/ ${env.DEPLOY_HOST}:/srv/app"
deps = ["build"]
env  = { NODE_ENV = "production" }

Override any variable from the command line with --var:

bash
$ kiln run deploy --var out=build

kiln init #

Create a starter Kilnfile in the current directory. kiln inspects the project and pre-fills tasks for detected tooling (npm, Cargo, Go, Make, Python).

kiln init [--template <name>] [--force]
FlagDescription
-t, --template <name>Use a built-in template: node, rust, go, python, blank.
-f, --forceOverwrite an existing Kilnfile.

kiln run #

Run one or more tasks and their dependencies. With no arguments, runs the task named in kiln.default.

kiln run [TASK...] [OPTIONS] [-- ARGS...]
FlagDescription
-j, --jobs <n>Maximum parallel tasks. Defaults to the number of CPU cores.
--no-cacheIgnore cached results and run everything.
--onlyRun the named tasks without their dependencies.
--dry-runPrint what would run, then exit.
--graphPrint the dependency tree and exit.
--var <k=v>Override a variable. Repeatable.
-k, --keep-goingContinue running unrelated tasks after a failure.

Arguments after -- are appended to the final task's command:

bash
$ kiln run test -- --reporter=verbose

kiln watch #

Run tasks, then re-run them whenever any of their inputs change. Only affected tasks in the graph are re-executed.

kiln watch [TASK...] [--debounce <ms>] [--clear]
FlagDescription
--debounce <ms>Wait this long after the last change before re-running. Default 150.
-c, --clearClear the terminal before each run.
--restartKill and restart long-running tasks (e.g. dev servers) on change.

kiln list #

Show every task in the Kilnfile with its description and dependencies.

kiln list [--json]
bash
$ kiln list
build   Compile and bundle the app
lint    Check code style
test    Run unit tests        → build
deploy  Ship to production    → build

kiln cache #

Inspect and manage the local cache.

kiln cache <status | clean | prune> [OPTIONS]
SubcommandDescription
statusShow cache size, entry count, and hit rate for recent runs.
clean [TASK]Delete all cache entries, or only those for one task.
prune --older-than <dur>Remove entries older than a duration such as 7d or 12h.

Global flags #

These work with every command.

FlagDescription
-f, --file <path>Use a specific Kilnfile instead of searching.
-v, --verboseIncrease log output. Repeat for more (-vv).
-q, --quietOnly print errors.
--color <when>auto, always, or never.
-h, --helpPrint help for the command.
-V, --versionPrint the version and exit.

Configuration #

User-level defaults live in ~/.config/kiln/config.toml (or %APPDATA%\kiln\config.toml on Windows). Project Kilnfile settings always take precedence.

config.toml
jobs   = 8
color  = "always"

[cache]
dir      = "~/.cache/kiln"
max_size = "5GB"

Every setting can also be provided via environment variable using the KILN_ prefix, e.g. KILN_JOBS=4 or KILN_CACHE_DIR=/tmp/kiln.

Exit codes #

CodeMeaning
0All tasks succeeded (or were cached).
1One or more tasks failed.
2Invalid usage or unknown task.
3Kilnfile parse error or dependency cycle.
130Interrupted (Ctrl-C).

Troubleshooting #

A task never hits the cache #

Run with -vv to see which input changed. Common culprits are generated files inside an input glob, or timestamps embedded in outputs that feed another task.

bash
$ kiln run build -vv
[debug] build: fingerprint changed
[debug]   ~ src/generated/version.ts

"No Kilnfile found" #

kiln stops searching at your home directory and at filesystem roots. Pass --file explicitly, or run kiln init.

Commands behave differently on Windows #

kiln uses sh on Unix and cmd.exe on Windows. Set shell = "pwsh" under [kiln] for consistent behavior, or keep commands to portable executables.
